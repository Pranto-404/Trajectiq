# Feature requests to shared owners

Feature engineers add requests here instead of editing shared files (src/store, src/ds, src/shell, package.json). Each entry: who asks, what, why, and the workaround in place.

## From WP7/WP8 (flight, crew), branch feat-flight-crew

1. **Store: consume the forecast in `ask`** (WP1, `src/store/createGame.js` `askAssistant`). The copilot answer for "Use my one forecast" carries `consumesForecast: true` but nothing increments `run.forecasts`, so "one forecast per mission" is not enforced (the v6 app had the same gap). Please do `set(s => ({run: {...s.run, forecasts: (s.run.forecasts || 0) + 1}}))` when `answer.consumesForecast` and a crisis is pending. Workaround: `spendForecast()` in `src/features/flight/IncidentTakeover.jsx` bumps `run.forecasts` through `useGame.setState` after `ask` resolves (the checkpoint writer persists it). Remove the workaround when the store does it; the test `the one forecast per mission` keeps passing either way as long as the count ends at 1.
2. **Store: `crew-signoff` re-opens `launch-check`** (WP1). `crew-signoff` always calls `gameReview()`, which replaces whatever sheet is open with `launch-check`. The standalone `rollcall` sheet (WP8) therefore turns into the built-in launch check after the first sign-off. Fine when the hangar embeds `<RollCall/>` in its own `launch-check` sheet; if you want the standalone sheet to stay open, make `gameReview()` skip `openSheet` when `sheet.id === 'rollcall'`.
3. **Hangar (WP5): use the crew components.** Replace the Go / No-Go block of the built-in `launch-check` with `import {RollCall, CrewStrip} from '@/features/crew/index.js'`: `<RollCall/>` reads the store itself (verdicts, sign-offs, solo or crew) and plays the sequential console animation; `<CrewStrip/>` is the crew table with pass-the-controls and proposals.
4. **Shell: `Stage3D` contract.** Flight loads `Stage3D` through `import.meta.glob('../stage/index.js')` (named export `Stage3D`), so it works before and after the stage package lands. If the stage exports it under another name or only as a default screen, tell WP8/WP7 or export `Stage3D` from `src/features/stage/index.js`. Props passed: `design, selected=null, hoverPart=null, run (read-only past view when scrubbing), phase, quality="auto", reduced, onPick, onSocketHover`. Until then the SVG `FlightSchematic` is shown.
5. **DS: gauge `compact` density.** `Gauge` has no compact form, so flight trims it with CSS (`max-width` on the arc dial, pair layout, hidden thresholds on short screens). A `size="sm"` prop (arc 100 px, linear without the foot row) would remove the overrides.
6. **Build hygiene:** `npm test` regenerates the committed legacy `dist/TRAJECTIQ_Play.html` (the legacy standalone builder runs inside a node test). It shows up as a modified file after every run; feature branches should not commit it. Consider making the test write to a temp file.
